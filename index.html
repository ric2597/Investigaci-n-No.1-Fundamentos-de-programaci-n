Introducción

Programar es describir una solución

Programar consiste en expresar instrucciones que una computadora puede ejecutar. Primero debemos entender el problema, identificar los datos y decidir qué resultado necesitamos.

Un algoritmo es un procedimiento ordenado para resolverlo. El programa expresa ese procedimiento con las reglas de un lenguaje.

Ejemplo cotidiano: calcular una compra. Necesitamos el precio y la cantidad. Multiplicamos ambos valores y mostramos el total.

precio <- 2.50
cantidad <- 4
total <- precio * cantidad
Escribir total // Resultado: 10
Base conceptual: CS50, Lecture 1. Ejemplo propio.03 / 42
1. Pseudocódigo

¿Qué es y para qué sirve?

El pseudocódigo describe los pasos de una solución mediante instrucciones comprensibles, parecidas al lenguaje cotidiano. Permite concentrarse en la lógica antes de escribir un programa en un lenguaje concreto.

Se utiliza para planificar algoritmos, explicar ideas y detectar pasos que faltan.

  • Legible: utiliza expresiones como Leer, Escribir y Si.
  • Ordenado: las instrucciones siguen una secuencia.
  • Preciso: cada paso debe tener un significado claro.
  • Flexible: no existe una única sintaxis universal.
Referencia: PSeInt, El pseudocódigo.04 / 42

2. Diagramas de flujo

La solución representada con símbolos

Un diagrama de flujo representa visualmente los pasos de un proceso. Los símbolos indican acciones y las flechas muestran el orden en que se realizan.

Sirve para planificar un algoritmo, comunicar su funcionamiento y revisar rutas posibles antes de programarlo.

  • Permite reconocer entradas, operaciones y resultados.
  • Hace visibles las decisiones y las repeticiones.
  • Ayuda a encontrar rutas incompletas o pasos innecesarios.
  • Complementa al pseudocódigo: ambos pueden representar el mismo algoritmo.
Referencia: IBM, What is a flowchart?07 / 42
2. Diagramas de flujo

Símbolos principales

  • Óvalo o terminal: comienzo o final.
  • Rectángulo: cálculo o asignación.
  • Paralelogramo: entrada o salida de datos.
  • Rombo: pregunta con rutas, normalmente Sí y No.
  • Flecha: dirección del recorrido.
  • Círculo con etiqueta: conector entre partes del diagrama.

3. Variables

Datos que pueden cambiar

Una variable es un nombre asociado a un valor que el programa utiliza. Durante la ejecución podemos reemplazar ese valor según la información recibida o los cálculos realizados.

Las variables sirven para conservar entradas, resultados intermedios, contadores y estados.

3. Variables

Declaración, asignación y actualización

Definir puntos Como Entero
puntos <- 0
puntos <- puntos + 10
Escribir puntos // Muestra 10

Declarar establece qué dato vamos a utilizar. Asignar guarda un valor. Actualizar sustituye el valor anterior por uno nuevo.

En puntos <- puntos + 10, primero se calcula 0 + 10. Después se guarda 10 en puntos. La asignación no es una igualdad matemática.

Nombres claros: precioUnitario, cantidad y total. Evita nombres ambiguos como dato1 cuando puedas describir su función.

4. Constantes

Valores que deben permanecer fijos

Una constante representa un valor que se mantiene durante la ejecución. Es útil para expresar reglas o cantidades que el programa debe reutilizar sin modificarlas.

  • DIAS_SEMANA = 7
  • PI_APROX = 3.1416
  • MAX_INTENTOS = 3

En JavaScript se puede declarar una constante numérica así:

const MAX_INTENTOS = 3;
En los ejemplos PSeInt de esta presentación, los valores fijos se asignan al inicio y se conservan por convención. Esa práctica no impide que el programador los cambie por error.
Referencia: MDN, const. Ejemplos propios.12 / 42

Condiciones y toma de decisiones

Una condición es una expresión que se evalúa como verdadera o falsa. Una estructura condicional utiliza ese resultado para decidir qué instrucciones ejecutar.

Permite responder de manera diferente a cada situación: aceptar un dato, aplicar un descuento o mostrar un aviso.

Operadores lógicos: Y, O y NO

8. Ciclos repetitivos

Repetir un bloque de instrucciones

Un ciclo ejecuta varias veces un bloque de instrucciones. Cada vuelta recibe el nombre de iteración.

Sirve para procesar listas de datos, pedir una entrada válida o realizar cálculos repetidos sin escribir una copia de las instrucciones para cada caso.

  • Control: establece cuándo se repite o termina.
  • Cuerpo: contiene las instrucciones repetidas.
  • Avance: cambia el contador o los datos que afectan la condición.
  • Terminación: debe ser posible alcanzar una salida.
Referencia: MDN, Bucles e iteración.26 / 42

8. Ciclos repetitivos

Ciclo Mientras

Definir contador Como Entero
contador <- 1
Mientras contador <= 3 Hacer
    Escribir contador
    contador <- contador + 1
FinMientras

Comprueba la condición antes de entrar al cuerpo. Continúa mientras esa condición sea verdadera.

Salida: 1, 2 y 3. Después de incrementar el contador a 4, la condición 4 <= 3 es falsa y el ciclo termina.

Puede ejecutarse cero veces. Si contador empieza en 4, el cuerpo no se ejecuta.

Cómo se construye un programa

Lo que aprendimos

  • La entrada aporta información y la salida comunica resultados.

  • Las pruebas de escritorio permiten comprobar rutas y resultados.
